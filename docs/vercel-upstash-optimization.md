# Vercel·Upstash 최적화 점검

점검일: 2026-10-24 (Asia/Seoul). 서울 리전 전환은 운영 적용했으며, 추가 코드 최적화는 아래 배포 기록을 따릅니다.

## 확인한 운영 상태

- 대상은 `qtaghdi` 팀의 `owkr-internal-balance` 프로젝트입니다.
- 기존 Production 커밋 `b1250b88ef518d622fda1cfca6c4ea8d1c37e759`을 서울로 재배포했습니다. 배포 `dpl_FiTXBxgwfSqKFrtrjCNxQeUBp7mB`는 `READY`, Node.js 24, `icn1`이며 운영 API 응답의 `icn1::icn1`도 확인했습니다. 기존 리전은 `iad1`이었습니다.
- 프로젝트 기본 리전과 이후 배포의 `vercel.json`을 모두 서울 단일 리전으로 맞췄습니다. [Vercel 리전 설정](https://vercel.com/docs/functions/configuring-functions/region)은 새 배포부터 적용됩니다.
- Vercel 비용·관측 API는 404, 환경 변수·연동 조회 API는 권한 403을 반환해 로그인된 대시보드로 확인했습니다. 운영 변수는 Production에만 연결돼 있고 Fluid Compute는 켜져 있습니다. CLI에는 별도 인증이 없어 인증 대기를 종료했습니다.
- Vercel 프로젝트 대시보드의 최근 30일 표시는 9월 24일~10월 24일, Functions 6,351회/1,000,000회, CDN 44,430회/1,000,000회, Fast Data Transfer 769.8MB/100GB, Fluid 메모리 1.1GB-Hrs, 활성 CPU 3분 42초입니다. Upstash와 집계 기간·단위가 다릅니다.
- Vercel 연동 Upstash `owkr-user-sheet`는 Free, AWS 도쿄 `ap-northeast-1` 기본 리전입니다. 월 명령 579,207회(쓰기 142,954회·읽기 436,253회)/500,000회로 차단 안내가 표시됩니다. 저장 공간 96KB/250MB, 대역폭 855MB/10GB, 표시 비용 $0.00입니다. 정확한 할당량 초기화 시각은 확인하지 못했습니다.
- Upstash의 TLS는 활성, 용량 부족 시 자동 키 퇴거는 비활성입니다. 이 저장소는 원본 자료와 세션을 보관하므로 자동 퇴거를 켜지 않습니다. 요금제나 복제 리전도 변경하지 않았습니다. [Upstash 공개 지원 리전](https://upstash.com/docs/redis/features/globaldatabase)에 서울은 없고 도쿄가 있으므로, 현재 한국 서비스의 Upstash는 도쿄를 유지합니다.
- 실시간 서버·로컬 Redis 게이트웨이의 공개 IP는 서울 Oracle로 조회됐고 공개 readiness는 200 `ready/redis`입니다. 실제 서버의 클라우드 제어판 리전과 시스템 시간 동기화 설정은 SSH 배포 경로 밖에서 직접 조회하지 못했습니다. 로컬 전달 파일을 이용한 게이트웨이 상태 조회는 401이어서 비밀값을 변경하거나 현재 pending 수를 추정하지 않았습니다.
- 런타임 오류 조회에는 `/api/match-shares`, `/api/notes`의 Node.js `url.parse()` 사용 중단 경고 그룹이 반환되었습니다. 이번 변경과 관련된 실제 실패나 비용 수치는 이 응답으로 판단할 수 없습니다.

## 반영한 변경

| 경로 | 변경 | 범위와 효과 |
| --- | --- | --- |
| 공유·공동 작업 생성 | 조회 후 저장 → `SET NX`와 만료 옵션 | 충돌 없는 생성의 Redis 명령 2개 → 1개. 충돌 시 덮어쓰기 방지 |
| 공동 작업 만료 | 상대 초 TTL → 생성 시점 `PXAT` | 네트워크·게이트웨이 대기로 저장이 늦어져도 생성 후 3시간 고정 |
| 공동 작업 장애 조회 | 3·6·12·24·30초 재시도 | 지속 장애 시 탭당 최대 약 2회/분. 성공하면 기존 활성 500ms·유휴 1.5초 복귀. 포커스 복귀는 즉시 확인 |
| 전체 동기화 | 접두사 7개별 전체 순회 → 전체 1회 순회 | `SCAN` 호출 감소. 기존 대상 접두사만 수집하고 writer·deploytest 키 제외 |
| 밴픽 활성 방 인덱스 | 매초 관리 조회는 같은 서버 Redis 사용 | 복구 후 빈 방 상태에서도 월 259만 회(30일×86,400초) 발생 가능한 원격 인덱스 조회 제거. 백업 동기화는 유지 |
| Upstash 한도 초과 | 일반 오류 재시도와 분리, 1시간 대기 | 일반 일시 장애의 지수 재시도는 유지. 한도 초과 중 로컬 쓰기가 원격 재시도를 깨우지 않음 |
| 동기화 삭제 | 키별 변경 시각이 직전 기록보다 증가하도록 보장 | 같은 밀리초의 삭제가 이전 원격 값과 동률이 되어 되살아나는 문제 방지 |
| 공개 정적 자료 | 브라우저 1시간·CDN 1일 캐시 | `/fonts`, `/tier`, `/hero`, `/background`, `/mascot`, `/draft-assets` 대상 |
| 수정 시각 표시 | 기기 기본 시간대 → `Asia/Seoul` | 공동 작업 활동·유저 시트 시각이 한국 시간으로 일치 |
| GitHub Actions 배포 | 기존 SSH 경로에서 설치된 게이트웨이도 갱신 | 사전 격리 Redis 검사·문법 검사·코드 백업·인증 상태 확인·실패 복구 포함 |

위 수치는 해당 경로의 명령·간격 기준입니다. 총비용 절감률은 사용량과 캐시 적중률을 측정해야 계산할 수 있습니다. 정적 파일은 같은 URL로 교체하면 브라우저에서 최대 1시간, CDN에서 최대 1일 이전 파일이 보일 수 있으므로 즉시 교체할 자료는 파일명도 변경합니다.

## 검증과 운영 반영

- `pnpm check`: 타입·린트·582개 앱 검사·도메인 경계·프런트/서버 빌드 통과. 배포 검사는 게이트웨이 갱신 성공과 게이트웨이·앱 실패 시 동시 복구를 포함합니다.
- 한국 시간 기반 내전 시작·설문 종료 계산과 기존 만료 정책을 확인했습니다. Vercel의 `TZ`는 [예약 환경 변수](https://vercel.com/docs/environment-variables/reserved-environment-variables)이므로 추가하지 않고 명시적인 한국 시간 변환을 사용합니다. 한국어 문서 언어·숫자 형식·정적 폰트도 확인했습니다.
- 일정·공동 작업 만료 검사 12개를 `TZ=UTC`, `TZ=America/Los_Angeles`에서 각각 통과했습니다. 여러 화면 변경에는 React 검사 지침도 적용했습니다.
- `python realtime/deploy/storage-sync-test.py`: 외부 저장소에 접속하지 않는 임시 Redis 두 개로 28개 통합 검사 통과. 만료 비연장, 일회 코드, 삭제·재시작 복구, 한도 대기 중 쓰기, 일반 장애 자동 복귀, 활성 인덱스 로컬 조회 포함.
- 프런트·Functions·캐시 설정은 Vercel 배포가 필요합니다. `storage-sync.py`는 별도 운영 서버의 게이트웨이 코드이므로 Vercel 배포만으로 적용되지 않습니다.
- 기존 Actions의 `REALTIME_SSH_HOST`, `REALTIME_SSH_USER`, `REALTIME_SSH_PRIVATE_KEY`를 그대로 사용합니다. 비밀값을 내려받거나 새로 등록하지 않습니다. 앱을 중지한 구간에서 설치된 게이트웨이 Python 코드 두 개만 백업·교체하고, 기존 Redis·SQLite 저널과 환경 설정은 유지합니다. 인증된 상태 확인 실패나 후속 앱 readiness 실패 시 게이트웨이 코드와 앱 릴리스를 함께 복구합니다.
- 인증된 `/storage/status`의 `upstream`, `pendingKeys`, `lastSyncAt`, `nextRetryAt`과 공개 readiness를 확인합니다. 한도 초과 중에는 로컬 읽기·쓰기를 유지하고 다음 확인까지 최대 1시간 기다립니다. 월 한도 초과 자체는 코드 최적화로 초기화되지 않습니다.
- 기존 설정으로 되돌릴 때도 동기화 저널·삭제 표식을 제거하지 않습니다.
- CDN은 한국 가까운 지점에서 정적 자료를 제공하며 Functions 리전과 별도입니다. 한국 전용 운영을 지리적 접속 차단으로 해석하지 않고, 인증·Origin·OAuth 콜백 도메인은 유지했습니다. Discord 외부 서비스의 자체 실행 위치도 앱에서 바꾸지 않습니다.
